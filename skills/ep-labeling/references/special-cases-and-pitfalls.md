# Special cases, pitfalls, history

Moved out of SKILL.md. Read the section you need. 字段与机制见 `photo-labeling-conventions.md`。

## 1. Close band pairs and cropped photos

**挨得极近的一对带（21/20 kD 这种）：一条标签盖两条带**

条带本身分得开（21/20 只差 ~1.2–1.6 mm，剖面上是两个峰；叫带的最小峰距是 0.05 cm），分不开的是**标签**：
8 pt 的字高约 2.4 mm，同侧竖直方向放不下两行字，换 dpi 也没用（字号与间距同比例缩放）。
Figure 的排字会把挨得近的标签上下让开（保持顺序），但真正并着跑的一对还是该合成一条：

```json
{"text": "21/20 kD", "rows": 2}
```

它在 Workbench 上变成**两条** band 线（`band 21`、`band 20`，各自参与标定），Figure 上是**一个**标签 `label band 21/20`，
落在两条线中间。`labels` 的行数之和仍要等于梯子上叫出的峰数，所以「数对不上就拒绝」的闸门照旧有效。

**照片是裁过的**（用户说「这张不是 15 条泳道」）：给 `--gel-lanes N`（N = 画面里看得见的泳道数）。
stage 1 改用 `N × lane_pitch_cm` 推可见宽度并据此定标，种子梳子也只有 N 齿；不声明就会拿裁后的画面
当整块 8.6 cm 胶，尺寸直接错。注意 `--gel-lanes` ≠ `--trim-lanes`：前者说「画面里有几条」（改定标），
后者说「Figure 里不要哪几条」（只影响出图）。

裁到胶**本身**（画面边就是胶面）时，认胶的严格口径会把胶当成「贴边的背景」丢掉 → 自动退回「允许贴边取最大块」，
日志 `[i] 胶面贴着画面边`。

## 2. marker 泳道配不上（梯子峰数 ≠ 标签行数）

render 按 `lanes.json` `marker_lanes`（再加 marker 预设的 `marker_lane`）的顺序逐条试，第一条配上的就是 marker 泳道；
每条失败打一行 `[!] marker 泳道 n 配不上：…`，全部失败才拒绝，消息里列出最后一条叫出的 y（cm）。不硬配：
按位置硬配出来的图看着正常、分子量却整体错位 —— 这是本 skill 出过的最坏的一种错。

按 y 值判断是哪种情况：

- **少一条、而且是这条梯子上确实没有的那条**（例如没跑出 35 kD；老批次在 IMG_1497 上就是手改 marker 标签凑的）：
  照预设 render 不了时，复制一份 markers.json、删掉那条标签再 render；或换一条完整的梯子泳道。
  若已经 render 出来了，在 Workbench 上**删掉 `band 35` 线**再 sync（它的标定点和 Figure 标签一起去掉），不要手改 marker 标签文字。
- **胶边损坏**（IMG_1497 泳道 1 压在胶左缘的破损上）：这条道的背景噪声高（1.88 灰度级），淡的 250 kD 被淹掉，只叫出 10/11，
  于是拒绝。列出**所有**梯子孔（`"marker_lanes": [1, 2, 3]`），render 自动换到泳道 2。
- **多叫一两条 / 位置明显不对**：先 `probe` 看每道叫出的 y 与噪声；或换梯子孔；
  已经 render 出来时，直接在 Workbench 上拖 / 删 / 改名 `band <MW>` 线，然后 sync —— 这就是现在的「手动标定」。
- 预设选错（同货号不同体系 Tris-Glycine / Tris-Tricine 的表观值不同）：换预设，重新 render（预设是 render 时的输入）。

## 3. 泳道种子不对

- **孔被切掉了**（`trim_top_cm` 太大、`--rect` 框得太低，或照片上孔区本来就看不见）：well_grid 只看胶面最上面 0.12 cm，
  看不到孔（孔深 < 20 灰度级）就退回「预设间距、整排居中」，日志 `看不清孔，预设间距居中`。这时种子没有锚定，可能整体偏半道到一道。
  处置：先修 stage 1 让胶面上缘落在孔底（去掉多余的 trim、修 `--rect`）再 render；或照常 render、请用户在 Workbench 上把泳道线拖正后 sync。
- **孔距与预设差 >10%**（`[!] scale: …`）：宽度定标或预设有一个不对，或照片裁过却没给 `--gel-lanes`。先问，不要改预设凑数。
- **个别泳道偏了**：不调参数、不重跑 —— 在 Workbench 上拖那两条线，sync。实测种子与手放泳道平均差 0.015 cm，偏差大多来自胶本身（smile、弯道）。

## 4. History and lessons

- **失效报告分析的是旧的安装副本（2026-10-22）。** 那份报告（IMG_1496–1500，15 孔 mini-gel，WJ103 marker）把错归到
  `pitch_from_row` / `split_wide` / `fill_gaps` / `snap_to_anchors` —— 它们早在 T3 就删了；报告跑的是一份过时的已安装 skill。
  教训：分析失败之前，先确认**跑的是哪一份 skill**（脚本路径、仓库提交、文档 `ep-meta` 里的 `skill_version`），
  旧副本先重新部署再复现；不要对着已删除的代码写修复方案。
- **`lane_pitch_cm` 0.565 → 0.52（mini-gel，2026-10-22）。** 0.565 是「15 道铺满整块 8.6 cm」反推的，假设错了：
  15 个孔只占约 7.8 cm，两侧各有 0.4–0.6 cm 没有孔。孔上实测 0.510–0.522 cm，用户在 IMG_1499 上手放平均 0.523 cm。
  15 × 0.52 = 7.8 cm，与 8.6 差 9.3%，仍在不变式 10% 的容差内。
- **IMG_1496 梯子落进泳道 2。** 老 stage 2（列墨量格点拟合）在样品道大多空/淡时没东西可锁，整体偏一道。
  现在种子按加样孔定相（conventions §6），梯子在泳道 1（用户确认）。同一批里被当作「空道 / 样品 1」的几道，按孔看其实是梯子：
  IMG_1497 孔 1–3、IMG_1498 孔 1–2、IMG_1499 孔 1–5、IMG_1500 孔 1–4。只有 IMG_1496 的版面经用户确认。
- **老 stage 3 的条带行一律偏下 0.13–0.5 mm**（5 张 DGC 照片，同一方向）。marker 线现在取剖面上叫出的峰。
- **样品带只深 3–4 灰度级**（梯子约 24）。任何绝对墨量门槛都会把整条淡道丢掉；现在门槛只相对于该道背景噪声（conventions §7）。
- **已删除的代码别再照着改**：`lane_fit.py` / `band_fit.py`（老 stage 2/3）、`scene*.py`、`editor.py`、`debug_overlay.py`、`record.py`，
  以及更早的「间距量自最密行 / 宽 run 劈开 / 按间距补位 / 锚点校正 / 行结构验伪」泳道启发式。

## 5. Pitfalls that still apply (stage 1, ImageMagick 7)

- **别拿「整块胶比背景暗」去找条带**：胶整块暗于灯箱。认胶用灯箱背景（环带样本拟的平面），条带只在胶面图上的泳道剖面里找。
- **别用 `-strip`**：IM7 里它会把之后设的 `-density` 一起丢掉。去元数据用 `+profile "*"`（胶面图就是这么写的）。
- **照片先 `-auto-orient`**：所有像素坐标（`--rect`）都是自动定向之后的原图像素。
- **`--angle` 是 magick `-rotate` 的语义**（正 = 顺时针）。只按竖边拟合的倾角旋正，没有透视矫正 —— 斜拍的梯形胶会保留失真。
- **蓝光灯箱**下 `chroma` 判据整屏都蓝，用默认 `dark`；染色胶在白光下两条判据框不一致时用 `--cue chroma` 或直接 `--rect`。
- **胶面上缘 = 孔底**：探测框上缘取第一条覆盖率 ≥90% 的行。旧的 50% 线落在孔间的齿中间，高度量出来是巧合。

## 6. VectorCraft pitfalls (summary)

全部实测记录在 `references/vectorcraft.md` §2。用到控制口时最常踩的：

- 没带 `--control` 启动的 VectorCraft 连不上，只能请用户存盘退出，再由 skill 带端口重启（不替用户关，会丢未存改动）。
- `document.find` 是**子串**匹配：`label lane 1` 会命中 `label lane 10`–`15`。按完整名字在 `document.json` 里找。
- 在锁定或隐藏的当前图层里 `text.create` 会把对象放进**别的**图层。新建标签只在 `labels`（不锁、可见）里做。
- 用户手动在 Layers 面板挪泳道进 `trimmed`：两条线都要挪（奇数条会被校验拒绝）；`trimmed` 必须保持不锁。
- `document.save` 返回时文件可能还没写完；skill 自己会轮询，手动读文件前也要等。
